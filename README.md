# LendItEazy — Synthetic Data Generation (Stage 3)

This workspace contains Jupyter notebooks that generate synthetic lending data following the Stage‑3 rules you described. The generated CSVs mirror the project data model and are intended for analysis, model prototyping, and building early‑warning logic.

## Folder layout

- `notebooks/` — notebooks that generate each table in order.
  - `01_generate_customers.ipynb` → creates `data/customer_profile.csv`
  - `02_generate_loans.ipynb` → creates `data/loan_details.csv`
  - `03_generate_outcomes.ipynb` → creates `data/loan_outcome.csv`
  - `04_generate_repayments.ipynb` → creates `data/repayment_behavior.csv`
  - `05_generate_signals.ipynb` → creates `data/behavioral_signals.csv`
- `data/` — output CSV files produced by the notebooks.
- `.scripts/` — helper scripts: `summarize_xlsx.py`, `analyze_xlsx.py`.

## Prerequisites

Install Python 3.8+ and required packages:

```powershell
pip install numpy pandas faker openpyxl
```

The notebooks set a `SEED` parameter for reproducible output. Change `SEED` at the top of a notebook to vary the generated data.

## Run order

1. `01_generate_customers.ipynb` — produces `data/customer_profile.csv` (required by later notebooks).
2. `02_generate_loans.ipynb` — reads customers and produces `data/loan_details.csv`.
3. `03_generate_outcomes.ipynb` — reads loans + customers and produces `data/loan_outcome.csv`.
4. `04_generate_repayments.ipynb` — expands loans into month-level repayments, writes `data/repayment_behavior.csv`.
5. `05_generate_signals.ipynb` — produces `data/behavioral_signals.csv` (monthly customer signals).

Run a notebook from the workspace root with:

```powershell
# run interactively
jupyter notebook
# or execute headless
jupyter nbconvert --to notebook --execute notebooks/01_generate_customers.ipynb --ExecutePreprocessor.timeout=600
```

## Key parameters (where to change)

- `N` / `TOTAL_LOANS` — total customers and loans (set in `01_...` and `02_...`).
- `SEED` — seed for deterministic generation.
- Employment split probabilities (in `01_generate_customers.ipynb`).
- Product assignment and product ranges (in `02_generate_loans.ipynb`).
- `BASE_RATE` and multipliers for default probability (in `03_generate_outcomes.ipynb`).
- DPD and repayment behavior probabilities (in `04_generate_repayments.ipynb`).
- Signal thresholds / volatility rules (in `05_generate_signals.ipynb`).

## Output schema and joins

- `customer_profile.csv` (primary key `customer_id`).
- `loan_details.csv` (primary key `loan_id`, foreign key `customer_id`).
- `loan_outcome.csv` (includes `loan_id`, `default_flag`, `default_month`, etc.).
- `repayment_behavior.csv` (rows per `loan_id` + monthly `dpd`, `amount_paid`).
- `behavioral_signals.csv` (monthly rows per `customer_id` with `stress_score` and signal flags).

The notebooks keep the `employent_type` column name (typo preserved) consistently across files; you can rename it to `employment_type` if preferred.

## Quick validation checks (run after each notebook)

- row count matches expected (`N`, `TOTAL_LOANS`, sum of tenures)
- employment split close to configured probabilities
- overall default rate ~ `BASE_RATE` after multipliers (approx 17%)
- DPD patterns: defaulters show worsening DPD before default
- signals: many defaulters show >=2 signals 1–2 months prior
